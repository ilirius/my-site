## Context

Мотивация — см. `proposal.md` (Why). Действующая спецификация `theming` описывает бинарную модель light/dark с манифестом «Silicon Desktop» и macOS-toggle. Макеты «Kinetic Portfolio System» и контракт `navigation-shell` требуют три режима (light/dark/system), токены teal `#5eead4` / тёмный `#0b1326` и сегментный переключатель.

Ограничения: механизм `.dark`-класса и селекторов `.dark`/`color-scheme` сохраняется; dark остаётся темой по умолчанию.

## Goals / Non-Goals

**Goals:**
- Перейти на три режима темы: light, dark, system.
- Обновить токены под Kinetic Portfolio System.
- Заменить macOS-toggle на сегментный переключатель (3 состояния).
- Определить резолв `system` через `prefers-color-scheme`.
- Зафиксировать персистентность выбора темы (localStorage-ключ `theme`).

**Non-Goals:**
- Не меняем механизм i18n и персистентность языка (ключ `i18nextLng` остаётся в `i18n`).
- Не проектируем содержимое шторки настроек (это `stitch-navigation-mapping-contract`).
- Не трогаем компоненты навигации BottomNavBar/VerticalDock.

## Decisions

### D1. Три режима через `.dark`-класс + `system`-резолв

**Решение:** хранить выбранный режим в трёхзначном поле (`light|dark|system`), а фактическую тему выражать прежним бинарным классом `.dark` на `html`. Режим `system` резолвится в `.dark` через `window.matchMedia('(prefers-color-scheme: dark)')` и слушатель `MediaQueryList` (`change`), который реагирует на смену системной темы без перезагрузки.

**Почему:** сохраняет существующий CSS-механизм (`.dark` + `color-scheme`) и всю существующую стилизацию; добавляет только слой резолва, не дублируя темы.

**Альтернативы:** отдельные классы `.theme-light/.theme-dark/.theme-system` — отвергнуто (ломает существующие селекторы и накопленные стили).

### D2. Токены Kinetic Portfolio System

**Решение:** тёмный фон `#0b1326`, светлая поверхность `#f8fafc`, акцент teal `#5eead4`.

**Почему:** соответствует утверждённым макетам Stitch; акцент `#5eead4` замещает прежний `#0a84ff` в переключателе и активных состояниях навигации.

### D3. Сегментный переключатель вместо macOS-toggle

**Решение:** переключатель темы — сегментный контроль (Light / Dark / System) с крупными скруглениями и пастельными поверхностями (Material You).

**Почему:** три состояния не выражаются бинарным macOS-toggle; сегментный контроль соответствует шторке настроек из макетов.

**Альтернативы:** три отдельных кнопки — отвергнуто (менее целостно, больше визуального шума).

### D4. Персистентность темы

**Решение:** localStorage-ключ `theme` хранит одно из `light|dark|system`; при инициализации читается до первого рендера (для избежания «мигания» темы — инлайн-скрипт или приоритет в `next/script`).

**Почему:** закрывает ранее открытый вопрос о ключе персистентности из `stitch-navigation-mapping-contract`; ключ `theme` не конфликтует с i18n-ключом `i18nextLng`.

## Risks / Trade-offs

- **[Риск] «Мигание» темы (FOUC) при восстановлении из localStorage** → Mitigation: восстановление до первого рендера (инлайн-скрипт в `<head>`), тёмная тема — дефолт.
- **[Риск] `matchMedia` недоступен на сервере (SSG)** → Mitigation: обращение к `window.matchMedia` только в эффекте/клиентском коде; SSR-рендер всегда с дефолтной тёмной темой.
- **[Риск] Конфликт с `stitch-navigation-mapping-contract`** → Mitigation: этот change определяет семантику `theme` до применения контракта; `NavigationStateSchema` уже использует `light|dark|system`.
